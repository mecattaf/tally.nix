## Method and coverage

- **Verified** means the shipped implementation agrees and an automated assertion pins the
  behavior. Each such row cites both implementation and check evidence.
- **Divergent** means the quoted doctrine and shipped behavior differ. Each such row cites the
  doctrine line in the claim column and the contrary implementation/check lines in the evidence
  column.
- **Divergent — presentation** is counted as divergent. The described set arithmetic is
  behaviorally sound, but the pseudocode presents an internal name as though it were the shipped
  reconcile-result vocabulary. The doctrine needs to label that name pseudocode-internal.
- **True-but-untested** means the implementation agrees, but no focused automated assertion was
  found. Source inspection, schema checking, or a test of only a downstream helper is not promoted
  to “verified.”
- Claims are split at independently falsifiable clauses. Repeated prose immediately following the
  pseudocode is covered by the same row when it asserts the same behavior. One ordered flow branch
  is one claim unless its independently enforced stages have different evidence.
- Headings, control-flow punctuation such as the final `exit`, historical explanations of a bug,
  hypothetical counterfactuals, security rationale, and recommendations are not behavioral claims.
  Their shipped consequences are covered. In particular, the `--first-parent` counterfactual at
  lines 1817-1818 is not a separate claim, while the actual `git log -m` walk and merge rejection
  each are.
- The old range ends on the blank line before “Squash merges and the steward's narration”; on the
  audited revision that boundary is line 1846. No claim beginning in the next subsection is
  included.
