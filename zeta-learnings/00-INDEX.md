session, immediately before its /compact. This folder is the durable memory
of that session: its findings, its operator rulings, and the paradigms that
are the house's secret sauce. It exists so the zeta chapter can be authored
from committed bytes, not from a summarized conversation. (The lineage's own
law, applied to itself: doctrine in prose decays; this is that prose given a
consumer — the zeta authoring sitting.)

## What zeta is

plane — the spec layer — *by campaign*, which makes it two things at once:
tally changing itself, and the first real "documentation-in" back-and-forth

EPSILON-EXTENSION stages (absorb ext0 / follow it / run beside it) — not
decided in the session; EPSILON-EXTENSION v2 remains the ratified program
until zeta is.

## The paradigms — the secret sauce shaped by tally

1. **Two planes, one repo.** Tally is the work plane (lanes, gates,
   receipts, release). The spec layer is the authority plane (claims,
   trace, ratification). Same store (git), same enforcement ladder.
2. **The provenance mark is the two-way valve.** Every claim is DECIDE
   (code must conform; oracle failure means the code is wrong) or
   `BELIEVE: path` (author's model of the system; tree disagreement means
   the spec is wrong). Plus `GUESS` on unsourced numerals and
   `[HUMAN-ATTENDED]` on oracle gaps. One token decides which side is
   authoritative per claim — that is what makes the layer two-way instead
   of proof-of-work one-way.
3. **Claim registry, not prose chapters.** Numbered falsifiable claims
   with stable number-derived anchors (`#r2`, IDs `2.1`), flat declarative
   arrow lines (`condition → observable`), vocabulary declared once,
   forbidden list in its own section near the end (recency), sections
   omittable with a reason (mandatory empty sections produce fabricated
   filler — the models' own testimony). EARS's discipline without its
   costume.
4. **Doubt gets a syntax and it blocks.** Unresolved GUESS / BLOCKING
   unknowns / DECISION-n items fail the lint; derivation is impossible
   while doubt is outstanding. The authoring model's confident and
   unconfident sentences are surface-identical ("fluency rises as
   grounding falls") — so honesty must be structural, never tonal. This is
   zero-transcription-acts at spec altitude: doubt becomes a typed queue
   on the inbox.
5. **Enforcement in the harness, not the prompt.** "Don't hallucinate"
   instructions cannot work; mechanical catching can. The authoring loop
   is author → lint → fix. The two rules that catch most real damage:
   unsourced numerals, and identifiers absent from provided context.
6. **Crystallize decisions, not code.** The essence/accident test for
   code→spec: a behavior earns spec status when a ruling or finding paid
   for it. The evidence ledgers (F/VD/PA/CA/EQ, D-register) are the
   crystallization input format the house already writes.
7. **Spec : worklist :: source : compiled.** The sitting is the compiler
   (human-attended; census + authoring + trace rows, one commit — which is
   also the arming act post-ext1). The worklist schema never changes; the
   spec points at tasks; the spec stays OUT of the epoch key (spec churn
   reaches budgets only through the sitting's precise task amendments).
8. **Every artifact names its standing consumer or dies.** The grind's
   bar rotted five days unexecuted (`--list`-only flake attribute); a bar
   without a gate is not a bar. The lint is the spec layer's standing
   consumer; the lint's own must-fail fixture proves it bites.
9. **Dual blind derivation for contracts of consequence.** Spec and
   conformance bar derived blind from one intent source; converge by
   collision; disagreements escalate as spec defects, never absorbed;
   evidence routed to workers is concrete-only (never the reasoning to be
   independently satisfied). Two measured limits: shared inputs are
   invisible to the method; unlit territory pays out serially.
10. **Byte-oracle-or-nothing + the oracle census.** Every claim binds to
    exactly one of: flake check attribute, witnessed gate argv, or
    HUMAN-ATTENDED. Zero or two bindings is a lint defect. Coverage is an
    enumeration, not a judgment.
11. **A spec is a delta-of-intent against a substrate.** Tally's three
    weeks and agency's 30M-line Chromium are the same problem at different
    magnitudes; agency's flag-off-behaves-stock gate is one giant
    unchanged-behavior clause; the Igalia patch-series/modifying-delta
    discipline is the divergence-spec kept small (expressible today as a
    `git diff --shortstat` gate argv).
12. **Ratification is an ordinary operator commit** — the push credential
    is the trust root; steer from anywhere, ratify at a keyboard; no
    machinery hand ever touches the authority file. The pin chain then
    runs ratified-spec sha → worklist sha → receipt → release: "which spec
    graded this code" is a lookup, not a claim.
13. **The placement law is the admission test for every mechanism** —
    each verb/field/rule enters only when it deletes an operator rule.
    The session's own rejected list (spec sha stamps, spec poll-admission,
    worklist keys, trailer schemes) shows it biting.
14. **Humans decide, never edit.** The human moments: irreversibility,
    unsourced constants, long-half-life names, genuine forks. Answers
    arrive as typed responses (steer/commit), never line edits — a patched
    spec loses the internal consistency that is the author's main
    strength. The most valuable review pass: "which of these statements
    about my codebase are false?"

## The value over Kiro / spec-kit (kept honest)

Their conventions are adopted (EARS discipline, traceability, unchanged
behavior; directory shape, wired constitution, converge stance). The
categorical differences: enforcement executable vs exhortative; two-way vs
one-way; proof (receipt chains) vs checkboxes; doubt as blocking grammar vs
uniformly confident prose; format elicited from the authoring model vs
imposed on it. One line: *they structure what an agent writes; the
authority plane governs what a factory proves — the only spec of the three
that can be wrong in a way a build notices.*
