V-1 — THE JOB MEMORY CAP: one unauthored global 8 GiB SIGKILL on every lane
- Constant: `--memory-max-bytes 8589934592` in nix/modules/home-manager.nix:28-29 and nix/modules/nixos.nix:29-30; the CLI REQUIRES it (crates/tally/src/cli/daemon.rs:32-36, no in-code default); one global unit_limits (tally-core/src/daemon/completion.rs:323) stamps MemoryMax= on every transient job (executor/launch.rs:28-32). Validation forbids expressing "no cap" (executor/lifecycle.rs:683 and daemon/mod.rs:355 reject 0 and u64::MAX).
- Origin: c4a23b48, 2026-07-20 initial public release. No ruling anywhere; absent from the caps replay.
- Bites / looks like: every compiling lane and every gate — cargo test --workspace runs inside the job cgroup and its parallelism scales with cores, so the cap bites BIG hosts hardest (inverts any protective intent). Presents as codex tool faults: tonight's 14 OOM kills read as `apply_patch verification failed` / `exec_command failed`, 5 hours burned.
- Disposition: delete the hard kill from job units (A6: no authored cap ever fired correctly; host memory + domain-disjoint scheduling are the real constraints). Host-level protection, if wanted, is a different mechanism: slice-level MemoryHigh= soft pressure or systemd-oomd — reclaim, not SIGKILL of a random child. Option-ification explicitly rejected.
- Regression guard: (i) executor unit test asserting build_systemd_argv emits no MemoryMax= when limits absent (red before fix); (ii) module-layer flake check asserts rendered daemonArgv contains no --memory-max-bytes; (iii) post-zeta substrate spec makes any reintroduced bare numeral a spec-lint build failure.
- Timing: boundary deploy only (A18 — the deployed store path grades). A10 group 1.

V-2 — THE DIAGNOSIS SANDBOX: hardcoded `read-only` default kills the diagnosing agent's own machinery (tonight's /dev/shm failure, chased to source)
- Constant: examples/flows/spec-build.js:2249-2254 — diagnosisSandboxed() stamps diagnosisSandboxPolicy:"read-only" unless the worklist explicitly sets the key (explicit values, including null, pass through the `!== undefined` guard); Rust parity default DEFAULT_AGENT_DIAGNOSIS_SANDBOX_POLICY = "read-only" (campaign_contract.rs:29, serde default :874-876; present key wins over default). The codex preset maps it to `--sandbox read-only` (nix/lib/adapters.nix:556-560) — codex's landlock sandbox, which denies ALL filesystem writes including /dev/shm and tempdirs.
- Origin: #298 c422453e (Aug 1, JS) and #429-433 072ffa76 (Aug 7, Rust). The POSITION (diagnosis must not mutate) is ratified — A20 and the in-file comment. The MECHANISM (the agent's own total-write-denial jailer) was never examined: it removes the scratch space codex's unified exec needs to exist at all.
- Bites / looks like: deterministic — any diagnosis node whose codex build spawns unified exec dies before reasoning: `mkdir -p /dev/shm/...` fails, "Failed to create unified exec process". Masquerade maximal: presents as adapter machinery fault, and it poisons the layer whose job is diagnosing everything else. Attribution (inference, marked): the denial being codex-internal rather than systemd is inferred from adapter hardening defaulting to None (adapters.rs:1549; no preset in nix/lib/adapters.nix sets hardening; no PrivateTmp/PrivateDevices reaches unhardened job units — nothing in the unit removes /dev/shm).
- Disposition: keep the read-only position, change the mechanism. Preferred: diagnosis default becomes `workspace-write` against a disposable worktree — codex itself mounts .git read-only under workspace-write (documented in the preset comment, adapters.nix:571-576), the worktree is discarded, diagnosis has no publish path; scratch space returns. Alternative (ext1-era): enforce read-only at the systemd layer (ReadOnlyPaths= on the checkout in a tailored hardening preset) with codex unsandboxed inside — the filesystem-authority split done by the substrate, not the agent's own jailer. Whether codex workspace-write permits /dev/shm specifically is inference — exactly what the verification step exists to prove.
- Regression guard: driver unit test pinning the rendered diagnosis argv's sandbox policy (fails if read-only returns as default); rehearsal fixture: dispatch a diagnosis-shaped codex invocation in a pristine worktree and assert unified exec spawns — tonight's repro inverted into a standing check.
- Timing: the FLOW default rides a boundary deploy — but the WORKLIST override needs none: campaign.agent.diagnosisSandboxPolicy is admitted worklist data honored against the deployed pin. See urgent flag 1 in part 3.
